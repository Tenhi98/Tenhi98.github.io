# SiteSnap 工地巡查（Claude 版）

这是参考原版 `sitesnap/` 重新写的一版：功能相同，修掉了原版的几个问题，并能打包成 Windows exe。
原版 `sitesnap/` 一行没动。

- 网页版：本目录（合并到 main 后网址为 `https://tenhi98.github.io/sitesnap-claude/`）
- Windows 桌面版：`desktop/`（Electron）

## 和原版相比

| | 原版 `sitesnap/` | 这一版 |
|---|---|---|
| 断网打开 | 打不开（离线缓存漏了首页） | 可以，安装时整个界面都存进缓存 |
| 相片保存方式 | base64 文字 | Blob，约小三分之一；另存缩图，列表更快 |
| 被浏览器自动清除 | 没有防护 | 第一次加相片时申请「持久保存」；资料页显示用量和上次导出时间 |
| 关闭页面时 | 最后几秒的修改可能没写入 | 切换程序、关闭窗口时立即写入 |
| 巡查份数 | 只有一份，导入会覆盖 | 多份巡查可切换；导入是「新增」，不会覆盖 |
| 优先级 | 无 | 观察 / 需跟进 / 紧急，列表和报告都有标示 |
| 报告 | 必须全部覆核才能预览 | 可随时预览；未覆核时盖「草稿」章；有封面摘要和索引；可两张一页 |
| 确认框 | 浏览器 `confirm()` | 页面内对话框 |
| 通行密码 | 有，但哈希公开、挡不住人 | 不设（资料只在本机，假密码反而给人错误安全感） |
| AI | 9 个服务商 | 8 家按产品名字母排序并列（Claude、DeepSeek、Doubao 豆包、Gemini、GLM 智谱、GPT、Grok、Qwen 通义千问），不预设任何一家；其他服务统一用「OpenAI 相容接口」。接口网址、地区、模型都显示出来，可自行修改 |
| 导出文件格式 | v1 | 同样是 v1，两个版本可以互相导入 |

## 能不能做成 exe？—— 可以，已经做了

我比较了四种做法：

| 做法 | 文件大小 | 优点 | 缺点 |
|---|---|---|---|
| **网页「安装为应用程式」**（Edge / Chrome 地址栏的安装按钮） | 0 | 不用打包，网站更新就自动更新；有离线缓存，断网也能用 | 不是 exe；资料跟浏览器绑定；公司电脑可能禁用 |
| **Electron**（本目录采用） | 约 110 MB | 技术最成熟；能直接存 PDF、用「另存新档」；AI 连线不受浏览器跨域限制，并使用 Windows 代理设定 | 文件大；更新要重新下载 |
| Tauri | 约 5–10 MB | 小，使用 Windows 自带的 WebView2 | 要装 Rust 工具链；在 Linux 上交叉编译 Windows 版很麻烦 |
| Neutralino | 约 3 MB | 最小 | 用本机端口提供页面，默认端口会变，一变资料库就「消失」（要手动固定）；功能少 |

**结论：** 公司电脑能用 Edge 的话，最省事是网页版「安装为应用程式」；需要真正的 exe（离线、锁死浏览器的电脑、要直接存 PDF），就用 Electron 版。以后嫌文件太大，可以把 `desktop/` 换成 Tauri，网页代码不用改。

### 桌面版的设计

- 网页版是唯一的原始码；`desktop/copy-web.cjs` 打包前把网页文件复制进去。
- 页面用固定的 `app://sitesnap/` 地址载入，所以资料库位置不会变。资料存在 `%APPDATA%\SiteSnap`，和浏览器里的网页版是分开的；要搬资料就用导出/导入。
- 网页拿不到 Node.js，只开放三个功能：存 PDF、存记录档、AI 连线（只接受 https）。
- 只允许开一个窗口，避免两个程序同时写同一个资料库。

### 怎样拿到 exe

1. **GitHub 自动打包（推荐）**：推送到 `claude/**` 分支、改到 `sitesnap-claude/` 时，`.github/workflows/sitesnap-desktop.yml` 会在 GitHub 的 Windows 电脑上打包。到仓库的 Actions 页 → 该次执行 → Artifacts 下载 `SiteSnap-windows`，里面有：
   - `SiteSnap-1.0.0-portable.exe`：免安装，双击就开
   - `SiteSnap-1.0.0-setup.exe`：安装版，有开始菜单和桌面捷径
2. **自己打包**（Windows 上装好 Node.js 22）：
   ```
   cd sitesnap-claude/desktop
   npm ci
   npm run dist:win
   ```
   exe 会在 `desktop/dist/`。

### 第一次打开时的提示

exe 没有数字签名，Windows 会显示「Windows 已保护您的电脑」：按「其他信息」→「仍要运行」即可。公司的 IT 政策可能完全禁止未签名程序；要正式发给同事用，需要另外购买代码签名证书（按年收费）。

## 测试过什么

- 网页版（Chromium 自动测试，25 项全部通过）：加相片、填写、覆核规则、重新载入后资料仍在、排序、报告和 PDF、中英切换、导出、导入（包括原版的记录档）、删除、**断网后重新打开**、手机宽度不横向滚动。
- 桌面版（同一份代码在 Linux 上跑 Electron，10 项全部通过）：`app://` 载入、网页拿不到 Node.js、存 PDF、存记录档、AI 连线拒绝非 https、**修改后立即关窗也有保存**、重开后资料仍在。
- Windows exe：已在 Linux 上打包成功，文件结构检查正确；**还没在真正的 Windows 电脑上运行过**。
- AI：9 个选项逐一自动测试（拦截请求，检查网址、认证方式和请求格式，22 项全部通过）；没有用真 API Key 连真服务测试。
